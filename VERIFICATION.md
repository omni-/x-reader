## Failed / corrected during development

- Google sign-in rejected the automated Chromium window. Normal installed Edge with the dedicated profile resolved the login handoff; no security controls or automation indicators were disabled.
- Tests caught `/i/status` validation, a missing challenge phrase, fixture encoding/long-text handler mistakes, and a test HTTP client's ignored Host override. These were corrected and the affected checks passed.
- Cancellation initially released the app lock before the first browser-close operation finished. Sharing the close promise fixed the native profile-lock race; the real-browser handoff and deadline tests passed afterward.
- Per-page budget stops were initially labeled as output limits when only queued work remained. Reporting now preserves the actual page-budget reason.
- Live continuation exposed a false ad exclusion on [this public video reply](https://x.com/NuclearStorm235/status/2101309942108188882): inner video `placementTracking` markup was mistaken for a promoted post. The filter now requires an enclosing ad wrapper or explicit promotion marker. The final HTTP traversal passed after correction. Regression tests also cover temporary empty virtualization frames and ancestor context rendered after the focal post.

No failures remain in the final automated suite or final live HTTP check. This does not imply complete conversation coverage.

## Unrun / limitations

- **ChatGPT account and tunnel end to end:** account eligibility, Platform tunnel permissions, workspace association, runtime authentication, `doctor` readiness and a ChatGPT tool invocation were not verified. No tunnel or public endpoint was created. Next: follow the README's Platform/developer-mode steps, provide the runtime key locally to tunnel-client, then run its documented `init`, `doctor` and `run` commands and connect the tunnel in ChatGPT.
- Live challenge/rate-limit/protected-account behavior was not deliberately triggered. Those stop states were tested with synthetic pages. Long-text and reply-control expansion have deterministic tests; live coverage is limited to controls encountered in the sampled public pages.
- No claim of exhaustive conversation coverage or verified exact parent edges is made. Observed root ID remains unknown in the inspected layout. Depth is a traversal budget, not an inferred exact reply graph. Recommendations and access-state detection depend on the recognized English UI; an unrecognized conversation layout fails closed.
- Search/profile continuation ends at a bounded stored snapshot. Thread continuation can expand pending branches, but does not promise replay of every root-page scroll beyond its per-page budget. Scroll-limited branches are reported explicitly.
- Images are screenshots of rendered post attachments and can be cropped by X. Videos are metadata-only. No quote-post enumeration, image OCR, sentiment analysis or internal LLM is implemented.
- Other operating systems and browsers were not live-tested. X can change its DOM or restrict automation at any time. X's prohibition on non-API website automation still applies.
